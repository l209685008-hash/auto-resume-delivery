# BOSS 自动招聘助手 · 财务关键词版

Chrome / Edge Manifest V3 扩展，版本 **0.5.6**。在 BOSS 直聘推荐牛人页面读取
可见候选人资料，只按两条硬条件判断，默认只扫描。

0.5.6 补两处真实页面差异：点完“打招呼”后按钮若变成“立即沟通”，也算发送成功（原先只认“继续沟通”，会误记未确认并连停三次）；
滚动改为即时并等 250ms 再量坐标，避免平滑滚动时量到动画中间的位置。

0.5.5 修复“不能打招呼”：候选人列表在 iframe 里时，原来靠 iframe 的 src 属性去匹配它当前地址，
SPA 改写或相对路径一出现就找不到，整轮直接停在“无法唯一定位候选人所在的 iframe”。
现在由候选框架自己逐级累加 frameElement 位置，嵌套 iframe 也能算准。另修：点击还没按下就失败时，
不再把该候选人永久记成“已发送”，并新增“清空发送记录”按钮用于人工恢复。

0.5.4 修一个会让**所有人**判“不符合”的缺陷：教育行回退取窗口时会往前跨进上一行（姓名），
再按换行截断，留下的恰恰是姓名，学历词被丢掉。推荐卡基本都先渲染姓名再渲染学历，
因此这是主线缺陷。另新增 `npm run verify:click`：真实 Chromium 加载扩展，
走 chrome.debugger 真实鼠标事件点一次“打招呼”，并验证重复运行不会给同一人再发一次。

0.5.3 修三处学历识别漏洞：提取器词表漏了“高职/研究生”，导致这类卡片判“未展示教育经历”；
“宁波某专科学校”这类校名里的学历词被整词丢弃；“在职 大专 会计学 期望岗位…”被内联拼成一整行时，
整词因含“期望”被丢弃。另加一条词表一致性测试，防止规则与提取器的学历词再次漂移。

0.5.2 学历门槛降到“大专及以上”：大专、专科、高职的财务相关专业也算符合；中专、中职、
职高、技校、高中及以下仍不通过。

0.5.1 修复摘要卡读不到学历的问题：原来要求“学校＋学历＋年份”三者齐全才算教育行，
而推荐牛人摘要卡常只写“本科 · 会计学”，导致专业一项永远判“卡片未展示教育经历”。
现在没有年份时回退到含学历词的短行，并排除“任职要求：本科以上”这类文案。

0.5.0 对照 GitHub 上仍在维护的同类项目做了一轮适配：补上招聘端真实卡片结构
（li.card-item / .candidate-card-wrap / .card-inner / button.btn-greet）与 data-geekid 身份属性；
点击后按钮文案与类名都会被重建，确认改为按卡片重新查“已沟通”控件，并补上“已联系/沟通过”等文案；
默认点击间隔由 0.5–0.9 秒放宽到 2–5 秒（同类项目实测用 2–5 秒与 25–70 秒）。

0.4.2 收尾审查遗留项：审计单条记录截断到300字、上限从3000条降到1500条，审计写入失败
只提示不中断筛选；删除已经用不到的薪资/英语/任职完整性提取代码，每张卡片少扫一遍。

0.4.1 修复代码审查发现的误判：学校名（如“上海立信会计金融学院”）不再冒充专业，
“广东外语外贸大学”这类校名也不再触发“外贸”关键词；关键词只扫工作与个人描述，
教育经历整行排除。顺带修好“专升本”“辅修”“培训”等写法导致的漏判。

0.4.0 把经验判定换成关键词命中：简历里出现“跨境电商、亚马逊、海外仓、退税”
等词就算通过，不再计算月份。专业条件从“财经类”收回“财务相关”，金融、经济、
国贸、工商管理等不算。两条都满足才打招呼，结论仍只有“符合/不符合”。

0.3.0 把六项条件收敛为两条，并**取消“待核实”**：证据不足一律按不符合处理，
理由写明缺少哪一项。
0.2.4 增加每次最多100人的扫描上限，与最多60次的打招呼上限分开设置。
0.2.3 修复超时被误报为“页面脚本尚未连接”，离线诊断保留脱敏的框架失败原因。
0.2.2 保留iframe精确补连、按钮去重和原任务停止控制。
0.2.1 弹窗宽度固定380像素，侧边栏随可用宽度伸缩。

## 本版筛选条件

| 条件 | 判断方式 |
| --- | --- |
| 大专及以上 · 财务相关专业 | 大专、专科、高职、本科或以上学历，专业属会计、财务管理、审计、税务、税收等；中专/高中及以下、金融/经济/国贸/工商管理/计算机等不通过 |
| 命中跨境电商关键词 | 工作与个人描述里出现跨境电商、亚马逊、海外仓、退税、出口退税、FBA、保税仓、独立站、速卖通、Shopee、Lazada、阿里国际站、外贸、报关、进出口、结汇、外汇等任一关键词（教育经历不参与，避免校名误触） |

两条都通过才算“符合”，才允许发送；任何一条不满足都记为“不符合”，
不存在“待核实”。证据区会写出命中的关键词和上下文原句（例如
“命中：跨境电商、亚马逊｜…深圳某跨境电商公司 负责亚马逊账务…”）。

关键词在 `src/content/financeRules.js` 顶部的 `KEYWORDS` 数组里，可自行增删；
同时命中的长词会吸收短词（命中“跨境电商”不再重复报“跨境”，命中“出口退税”
不再重复报“退税”）。校名与院系名整词剔除后再判专业（中央财经大学、上海立信会计
金融学院读计算机都不通过）；专业课程、辅修专业、岗位要求、培训经历也不能替代
所学专业。

只依据简历文本。年龄、性别、出生日期、婚育情况不参与筛选或发送决策。

## 安装与使用

1. 解压发布包，打开 Chrome 的 `chrome://extensions/` 或 Edge 的
   `edge://extensions/`，开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的目录。
3. 打开 BOSS 推荐牛人页面，选中要筛选的岗位，点击扩展图标。
4. 默认“只扫描”。面板只显示符合、不符合，以及每条判断的原始证据原文。
5. 确认筛选结果后，可切换到“筛选并打招呼”再点击开始。只有两条全部通过
   才可发送；页面岗位不能明确识别时只允许扫描。
6. 可打开侧边栏持续查看状态；运行时也会在页面显示停止按钮。

更新时请先停止旧任务，在原已加载目录更新文件后，点击同一扩展的重新加载，
确认扩展详情显示0.4.0，以保留扩展ID和本地防重记录。不要同时启用多个版本。
Chrome与Edge的扩展安装及本地记录相互独立，切换浏览器不会迁移防重记录。
在 `https://www.zhipin.com/web/chat/recommend` 打开新版面板并点击“重新连接”，
插件会尝试补连缺失脚本，无需自动刷新BOSS页面。
若仍显示等待候选列表，可点击“导出页面诊断”，其中仅含页面路径、版本、
iframe连接状态、控件数量及CSS结构，不含候选人姓名或简历正文。

摘要卡片常不展示专业或完整工作条目。缺少证据会直接判为“不符合”并在
理由里写明是“证据不足”，不会自动补全事实。当前适配读取卡片内结构化工作/
教育区块，不自动打开或导航到完整简历。岗位标题和工作区块的选择器集中在
`domSelectors.js` 与 `profileExtractor.js`，网站改版后可能需要更新适配。

## 执行边界

- 每次最多扫描100人，可设置更低的扫描上限；“最近候选100人”另为显示上限。
- 打招呼每次最多60次尝试，仅页面同一按钮出现“继续沟通”等状态才计成功。
- 发送前持久保存候选人记录；结果不明确也不会重试。清空审计不清空防重记录。
- 一次只有一个运行任务；停止、岗位变化、页面跳转或连接异常后禁止继续点击。
- 验证码、登录、安全验证、频率或次数限制会停止；连续三次未确认会停止。
- 不自动刷新、导航、切换岗位，不绕过平台验证。
- 默认点击间隔2–5秒（可调，下限0.5秒），另包含必要的定位、滚动与页面确认等待。同类招聘端项目
  实测用2–5秒甚至25–70秒，间隔过短更容易触发风控。

## 数据与权限

候选证据、最近100条结果、最多1500条审计（单条证据截断到300字）和防重发送记录保存在本机扩展存储。
扩展不调用外部AI接口或上传简历。JSON导出可能包含候选人姓名及经历证据。

`storage` 用于本地记录，`activeTab/tabs/scripting` 用于连接当前BOSS页面，
`webNavigation` 用于识别候选列表所在iframe与停止失效任务，`debugger` 用于
在已确认的按钮区域执行一次鼠标点击，`sidePanel` 用于持续显示工作台。
调试连接在点击后释放。网站权限仅限 `https://*.zhipin.com/*`。

## 参考的同类项目

0.5.0 的选择器、身份属性和节奏参数对照了 GitHub 上仍在维护的同类项目（均为 2026-11 仍在更新）：

| 项目 | 方向 | 参考点 |
| --- | --- | --- |
| [KuroNya39/boss-candidate-tool](https://github.com/KuroNya39/boss-candidate-tool) | 招聘端（Electron + CDP） | 推荐页真实结构 `li.card-item` / `.candidate-card-wrap` / `.card-inner` / `button.btn-greet`、`data-geekid` 身份属性、点击后按钮文案与类名会重建、已联系/沟通过文案 |
| [ga-ven/boss-hire-automation](https://github.com/ga-ven/boss-hire-automation) | 招聘端（CDP + boss-cli） | 限速区间（25–70 秒）、单轮上限、连续失败熔断、页面内与跨天两层去重；实测“打招呼后页面状态仍显示可打招呼”，所以去重必须靠本地状态库 |
| [Ocyss/boss-helper](https://github.com/Ocyss/boss-helper) | 求职端（WXT + Vue，2.5k★） | 直接调用站内 `/wapi` 接口并用 `bst` cookie 作 token 的做法；本项目**未采用**（见下） |
| [gstranded/autocast-boss-assistant](https://github.com/gstranded/autocast-boss-assistant) | 求职端扩展 | MV3 扩展的投递前置筛选与批量节奏 |

**为什么没有改成直接调接口**：接口直连能绕过 DOM 抓取，速度和稳定性都更好，但打招呼会变成一次纯 API 请求，行为特征比真实鼠标点击更明显，且接口字段随时可能变。本项目保留“真实鼠标点击 + 页面确认”的路径，把它当作安全边界。

## 开发与验证

使用 Node.js 20+、PowerShell 和 Chrome/Chromium；Edge实测另需本机安装Edge。

```powershell
npm ci
npm test
npx playwright install chromium
npm run verify:browser
npm run verify:popup
npm run verify:edge
npm run verify:click
npm run build
```

规则模块为独立纯函数；测试包含日期与去重边界、缺失证据、跨条目误匹配、
英语否定表达、薪资币种/周期、单任务控制与不确定发送防重。
浏览器回放使用本地合成页面和模拟Chrome接口；Edge验证另在独立临时配置中
实际加载MV3扩展并扫描本地合成iframe，所有网络由本地拦截，零点击、零发送。
`verify:click` 会在临时 Chromium 配置中加载扩展，把 www.zhipin.com 解析到本地 HTTPS 服务，
走完“内容脚本 → 后台 → chrome.debugger 真实鼠标事件”的完整链路，并验证重复运行不会重复发送；
它仍然不等于已验证用户当前 BOSS 页面的真实 DOM，但覆盖了真实点击这一步。
发布脚本校验JS语法、Manifest引用、ZIP文件数量及每个文件的SHA-256一致性。

详细设计见 [岗位设计](docs/finance-edition-spec.md)，本次验证记录见
[验证报告](docs/verification.md)。本仓库暂未授予开源许可证。
